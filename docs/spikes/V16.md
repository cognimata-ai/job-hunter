# V16: the TypeScript 7.0.2 toolchain

## Assumption

The frontend toolchain of the spec (§4.1: Vite 8.3.4, React 19.3.1, openapi-typescript 7.13.0, vitest 5.0.5) builds,
lints and type-checks cleanly with TypeScript 7.0.2, including the Vite 8 React plugin, eslint with
typescript-eslint, and the generation of `src/api/schema.d.ts` (spec §14.5, §22 V16). Otherwise the frontend stays
on TypeScript 5.9.3.

## Method

`frontend/package.json` pinned `typescript@7.0.2` and the other tools exactly (no `^` or `~`; the † versions are
the newest ones that were compatible at install). With it, in `frontend/` on Node 22.22.0 and npm 10.9.4:

1. `npm install`;
2. the same install again with `--legacy-peer-deps` (in a scratch copy, so that no forced resolution reached the
   committed lock), then `npm run build`, `npm run typecheck`, `npm run lint`, `npm run gen:api` and
   `npx vitest run` against it;
3. for the fallback, `typescript@5.9.3` in `package.json`, `npm install`, the same five commands plus
   `npm ci` from a removed `node_modules`.

Step 2 also checked that `tsc 7.0.2` is not vacuous: a file with `const n: number = "x"` fails it.

## Observed result

**TypeScript 7.0.2 does not work with this toolchain. It fails twice, and `gen:api` and `lint` fail even when the
install is forced.**

- `npm install` stops with `ERESOLVE`: `openapi-typescript@7.13.0` has the peer dependency `typescript@^5.x`
  and `typescript-eslint@8.71.2` (with its `@typescript-eslint/*` packages) `typescript@>=4.8.4 <6.1.0`.
- With `--legacy-peer-deps`, the install succeeds (163 packages) and:

| Command | Under 7.0.2 |
|---|---|
| `npm run build` (Vite 8.3.4, `@vitejs/plugin-react` 6.1.2) | passes; `dist/index.html` has no inline script or style |
| `npm run typecheck` (`tsc --noEmit`, version 7.0.2) | passes, and fails on a real type error |
| `npx vitest run` | passes (the tests do not use the TypeScript API) |
| `npm run lint` | **fails** at startup: `Error: typescript-eslint does not support TS 7.0.` The message points to running typescript-eslint on the TS 6 API side by side and to typescript-eslint issue 10940 (support for TS >= 7.1) |
| `npm run gen:api` | **fails**: `TypeError: Cannot read properties of undefined (reading 'createKeywordTypeNode')` at `ts.factory` in `openapi-typescript/dist/lib/ts.mjs`. `require("typescript")` of 7.0.2 exports `version` and `versionMajorMinor` only: the JavaScript compiler API that openapi-typescript and typescript-eslint use is gone |

- With `typescript@5.9.3`, the install resolves without a peer conflict (162 packages) and
  `npm run build`, `npm run typecheck`, `npm run lint`, `npm run gen:api` (686 lines of `schema.d.ts`) and
  `npx vitest run` all pass.
- `npm ci` from a removed `node_modules` installs from `package-lock.json` without changing it (sha256 of the
  lock before and after is equal), so the lock reproduces.

## Decision

The frontend uses **TypeScript 5.9.3**, as the spec's fallback says (§4.1, §22 V16). `package.json` pins it, and
`package-lock.json` is committed so that `npm ci` reproduces the install.

TypeScript 7 stays out until both tools that need the JavaScript compiler API support it: openapi-typescript (peer
`^5.x`; no TS 7 support in 7.13.0) and typescript-eslint (support for >= 7.1 is tracked upstream). Re-run this spike
when either releases that support. Until then, `tsc 7.0.2` itself already passes the type check and the build, so
it can be tried later as the type checker only, beside 5.9.3 for the two tools.

# V13: structured output on a stream, and the fields it exposes

## Assumption

Spec §10.1 G2, G8, G10 and §22 V13. `ChatAnthropic(...).with_structured_output(Schema, method="json_schema",
include_raw=True)` with `streaming=True` gives the gateway these fields in `raw.response_metadata` /
`usage_metadata`:
- `stop_reason`;
- `stop_details`;
- the served `model`;
- the cache usage fields.

The request carries `output_config.format` and `output_config.effort`, and no `tool_choice`. Where a field is
missing, the gateway reads it from the raw `anthropic` event stream through its subclass (plan Task 4).

## Method

Two paid calls on 2026-10-21, after a `--dry-run` that built both requests offline:

    uv run python scripts/spikes/record_anthropic.py --spike v13 --live

The recorder (`scripts/spikes/record_anthropic.py`) ran the definitions in `scripts/spikes/v13_structured_stream.py`:
- one call to `claude-sonnet-5-5`, then one to `claude-opus-5-5`;
- the §11.12 query proposal schema literal, with a top-level `title` added (langchain names a dict schema by its
  title, and refuses one without);
- effort `low` and `max_tokens` 1,024;
- the purpose `propose_queries`;
- a synthetic profile of an invented candidate, with no name, contact or employer.

Each call went through the production code: `gateway._chat` on `transport.make_http_client(cfg, mount=…)`, where
the mount was the recorder's capturing transport over a direct connection. The capture asked for
`accept-encoding: identity`, so it holds the stream exactly as the SDK parsed it. The key came from the worker
`anthropic_key` secret, loaded from a temporary file that the recorder deleted at once. The spike's `check()`
read the field paths of each call: from the captured request, from the parsed SSE events, and from langchain's
`raw` message. It recorded names, model ids, stop reasons, token counts and booleans, never content.

**Spend.**

| Call | Input bound | Worst case (reserved before the send) | Usage in / out | Settled |
|---|---|---|---|---|
| Sonnet | 2,335 | $0.016078 | 741 / 409 | $0.005572 |
| Opus | 2,335 | $0.032155 | 741 / 400 | $0.010964 |
| **Total** | | **$0.048233** | | **$0.016536** |

That leaves 6 of the 8 M2 messages and $0.751767 of the $0.80 worst-case sum. Each input bound is the byte

## Observed result

Both calls returned HTTP 200 with `stop_reason='end_turn'`. Both parsed, and both answered in the requested
model. Every field V13 asks about was present.

| Field | Path with `streaming=True, include_raw=True` | V13 |
|---|---|---|
| stop reason | `out["raw"].response_metadata["stop_reason"]` | `end_turn` (both) |
| stop details | `out["raw"].response_metadata["stop_details"]`. It is present only when not null, because langchain adds it with `if stop_details := …`; on a refusal it is the SDK's `RefusalStopDetails.model_dump()`: `{"type": "refusal", "category": …, "explanation": …}` | absent (the SSE `message_delta.delta.stop_details` was `null`) |
| served model | `out["raw"].response_metadata["model_name"]`, from `message_start.message.model`. The key is `model_name`, not `model` | equal to the requested model (both) |
| cache read | `out["raw"].usage_metadata["input_token_details"]["cache_read"]` | 0 |
| cache creation | `out["raw"].usage_metadata["input_token_details"]["cache_creation"]` | 0 |
| input tokens | `out["raw"].usage_metadata["input_tokens"]`. langchain **adds** the cache read and creation tokens to the API's `input_tokens` | 741 (= SSE 741 + 0 + 0) |
| output tokens | `out["raw"].usage_metadata["output_tokens"]`; thinking at `output_token_details.reasoning` | 409 / 400; reasoning 0 |
| provider request id | **not exposed**: only the HTTP response header `request-id` carries it | — |
| message id | not exposed when streaming | — |

- **The request.** The body keys were `max_tokens`, `messages`, `model`, `output_config`, `stream`, `system`
  and `thinking`:
  - `stream: true` and `max_tokens: 1024`;
  - `output_config.format = {"type": "json_schema", "schema": anthropic.transform_schema(literal)}`, byte-equal
    to the transformed literal;
  - `output_config.effort: "low"`;
  - `thinking: {"type": "adaptive", "display": "summarized"}`, which langchain adds by itself because the model
    profile lists `xhigh`;
  - `system` as a string, and one `user` message with string content;
  - no `tool_choice`, `tools`, `temperature`, `top_p` or `top_k`.

  The headers included `x-jh-purpose: propose_queries`, `x-stainless-read-timeout: 120.0`,
  `x-stainless-retry-count: 0` and `anthropic-version: 2023-06-01`.
- **The stream.** Both calls sent the same events:
  - `message_start`, `content_block_start` (one `text` block), `ping`, `content_block_delta` (`text_delta`, many),
    `content_block_stop`, `message_delta` and `message_stop`;
  - **no thinking block** on either model at effort `low` (`thinking_tokens: 0`).

  Inside them:
  - `message_start.message` carried `container`, `stop_details` and `diagnostics`, all null.
  - Its `usage` carried the `cache_creation` breakdown (`ephemeral_5m_input_tokens`,
    `ephemeral_1h_input_tokens`), plus `service_tier`, `inference_geo` and `speed`.
  - `message_delta.usage` is cumulative, with `input_tokens`, `cache_creation_input_tokens`,
    `cache_read_input_tokens`, `output_tokens` and `output_tokens_details.thinking_tokens`.
  - langchain builds `usage_metadata` from `message_delta.usage`, which has no `cache_creation` breakdown, so
    `input_token_details` holds exactly `cache_read` and `cache_creation` when streaming.
- **The response headers** were:
  - `request-id`, `anthropic-organization-id`, `anthropic-workspace-id` and `cf-ray`;
  - the `anthropic-ratelimit-*` counters of the account;
  - `traceresponse`, `cache-control`, `content-type`, `date`, `server`, `vary`,
    `strict-transport-security`, `content-security-policy`, `x-robots-tag`, `cf-cache-status` and
    `transfer-encoding`.

## Decision

- **No subclass hook is needed for these V13 fields.** Task 5 reads them as follows:
  - `stop_reason = raw.response_metadata["stop_reason"]`.
  - The refusal category is `(raw.response_metadata.get("stop_details") or {}).get("category") or
    "unspecified"`. A missing key means null.
  - `model_served = raw.response_metadata["model_name"]`.
  - For the settlement's `pricing.Usage`, take `cache_read = input_token_details.get("cache_read") or 0` and
    `cache_creation = input_token_details.get("cache_creation") or 0`, and then
    `input_tokens = usage_metadata["input_tokens"] - cache_read - cache_creation`. Using langchain's
    `input_tokens` as it is would bill the cache tokens twice.
- **The provider `request-id` (G10) is the one field langchain does not expose**, so the gateway reads it from
  the HTTP response. For example, `GatewayChatAnthropic` can override `_acreate` to keep
  `raw_response.headers["request-id"]`, or an `httpx2` response hook can write it into a per-call holder.
  Either is Task 5's (G10). The fake sends a synthetic `request-id` header (`req_fake_NNNN`) on every answer
  for it.
- **The recordings.** The two streams are committed under
  `tests/contract/fixtures/anthropic/propose_queries/<model>/2a340f1b74a0.sse`, the layout `llm/fake.py`
  serves.
  - The message id is replaced by `msg_recorded_<schema12>`.
  - The response headers keep `content-type` only: `request-id`, `anthropic-organization-id`, `cf-ray`, the
    workspace id and the rate-limit counters are removed.
  - The thinking placeholders went unused, because no thinking was streamed.
  - `<schema12>.components.json` holds the component byte sizes and the recorded usage, for Task 6's bound
    check.

  Both streams are synthetic-input recordings, and they pass `tests/contract/test_fixture_pii.py`. They serve
  V13 and `tests/unit/test_fake_llm.py` only. Tasks 13 and 20 hand-author their streams with
  `tests/support/llm.synthetic_sse`, which reproduces the event shapes above.

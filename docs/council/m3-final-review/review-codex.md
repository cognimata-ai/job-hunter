**I1 — Eval eligibility counts cases the run never evaluated** — [eval_calibration.py:138](/home/user/job-hunter/backend/src/jobhunter/scoring/eval_calibration.py:138).

The runner snapshots active case IDs once at [eval_runner.py:1090](/home/user/job-hunter/backend/src/jobhunter/scoring/eval_runner.py:1090), but calibration reads the current active user-case count at completion. Start a run with ten user cases, then add or activate twenty while it runs: the original ten supply all observations, while thirty satisfy the calibration threshold. The synthetic probe produced `primary=10`, `paired=10`, and `passed` with `active_cases=30`; the same metrics were `uncalibrated` with ten. That saved `passed=True` can subsequently satisfy activation ([validate.py:435](/home/user/job-hunter/backend/src/jobhunter/settings/validate.py:435)).

Fix by recording the run’s eligible cohort and deriving its calibration count from the user cases actually covered by that cohort, with explicit handling of missing results. Cases added during execution must not promote an under-thirty run into calibrated evidence. Add a regression that changes case membership between selection and completion. This preserves T20-b’s exclusion of adversarial fixtures from the thirty-case threshold.

**I2 — Publication truncation discards critic confirmation and removes a knockout penalty** — [publication.py:263](/home/user/job-hunter/backend/src/jobhunter/scoring/publication.py:263).

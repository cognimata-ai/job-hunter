### 1.4 Shared gaps
- All three: the structured-output schema subset is UNVERIFIED (F9/C8). Add a payload test that posts each schema once with `max_tokens` small and asserts no 400 (counts as one call; cheap).
- All three assume a 5-minute cache TTL is kept warm across a run. With `max_concurrency` 3–4 and critic calls on ~30 % of ads this holds, but a run that pauses for an embedding batch > 5 min pays a new write. Record it; it is visible in `cache_creation_input_tokens`.
- Nobody verified Opus/Sonnet thinking-token variance on this task; every cost table should carry a sensitivity line (O has one).

## 5. TOP 5 DISAGREEMENTS

1. **Separate facts-extraction LLM call and LLM-fact gates (O) vs facts inside the generator and gates on structured data only (F/C).** O's gate caps an ad at 25 when two LLM readings of the same text agree, with no critic in the loop (O4); it also costs a third LLM call per ad (~$0.026 of A's $0.103). Folding facts into the generator keeps one call, and routing any LLM-derived "mandatory" mismatch to the critic turns a plausible wrong gate into a `contested` badge instead of a bottom-ranked ad.
2. **Pre-filter semantics: τ threshold with anchor ads + top-N (O) vs slot allocation with no permanent rejection (C, adopted by F).** A threshold needs a calibrated band per embedding model and per profile (O5 leaves the anchors' provenance open); allocation needs only a rank. With C's 20 % oldest-pending lane every eligible ad is eventually scored or expires as an explicit outcome, so recall is a queue-age metric, not a hoped-for audit hit.
3. **Process topology: C's scheduler container + lease/fencing + outbox vs one worker + DB constraint + procrastinate lock (F/O).** The deployment runs one worker; the partial unique index already makes a second active run unrepresentable. Fencing generations guard a multi-worker race the compose file forbids, and the outbox adds a delivery path whose at-least-once semantics then require idempotency keys everywhere. Simpler is also more reviewable.
4. **Displayed/ranked score with unknown criteria: C's midpoint `(L+U)/2` vs O's renormalisation vs ranking by the lower bound.** Midpoint gives 50 % credit for missing evidence (C3); renormalisation gives unknowns the average of knowns (one known 4 → 100). Rank and display by the lower bound with the interval and coverage shown; it pushes partial-text ads down for a reason the user can see, and it is the only variant where "more evidence can only raise the score".
5. **Quota settlement details: O's JSearch header-delta billing detection under concurrency, and the ambiguous `max(local, remote)` comment vs status-based settlement + "reported balance never raises local" (C).** Under `max_concurrency=6` the header delta misattributes bills (O2); settle 2xx as billed, treat timeouts as `unknown` (spent), reconcile from headers/account.json only downward, and run JSearch at concurrency 1. Disagreement is small but it is the one place where a wrong implementation silently overspends.

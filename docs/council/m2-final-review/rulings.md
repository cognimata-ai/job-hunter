## Spec inconsistencies for the spec owner

1. **§6.8 against §13.1 (Arbeitnow).** With its constants, the `arbeitnow_coverage_risk` warning cannot fire anywhere in §13.1's interval range of 1–168 h, because h/37 < ceil(h/30) holds for every h in it. Deviation 39 keeps the check as a guard, and a unit test sweeps all 168 values.

A save that changes only the timezone therefore leaves the schedule anchored in the old zone. The fix is either to make `display.timezone` class `schedule`, or to re-anchor on every save.

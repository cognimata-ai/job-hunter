#### Minor

**R2-M1** — A rename of `_wrapApiCall` surfaces locally as a 300 s readiness timeout with a misleading message, because `ready()` swallows every error — `frontend/e2e/global-setup.ts:13-16`, `frontend/e2e/support/api.ts:72, 81` — Scenario: a developer bumps Playwright to a version that renames the private method and runs `npm --prefix frontend run e2e` on a healthy stack; `context.get("/readyz")` throws `TypeError: internal._wrapApiCall is not a function` inside `ready()`'s `try`, the `catch` returns `null` ("devproxy or the api not up yet"), `waitFor` polls for five minutes and fails with `GET /readyz 200`; the stack was fine. CI is loud because `e2e:sentinel` runs first (`e2e.yml:58-59`) and names the TypeError in its tail; a local run is not. — Fix: in `newApiContext`, check the method once at creation, outside any caller's `try` — `if (typeof internal._wrapApiCall !== "function") throw new Error("Playwright's _wrapApiCall is gone: newApiContext needs 1.56.1's client (see support/api.ts)")` — so the failure names its cause at the first context.

**R2-M2** — The lint rule leaves three ways past `newApiContext` open — `frontend/eslint.config.js:27-35` — Scenario (probed in memory against the real config): `const { request } = page; await request.get(…)` passes (`:function > ObjectPattern` matches a parameter pattern only, not a declaration's), `page["request"].get(…)` passes (a computed member has no `property.name`), and `import { request } from "playwright"` or `"playwright-core"` passes (`no-restricted-imports` names `@playwright/test` only; `playwright-core` is a direct dependency through `overrides`). A spec written that way sends an authenticated request whose transport failure carries the cookie into the report, which nothing scans. None exists today, and the fixer's concern 3 names the third. — Fix: `ObjectPattern > Property[key.name='request']` without the `:function >` prefix, a second selector `MemberExpression[computed=true][property.value='request']`, and `playwright` and `playwright-core` added to `REQUEST_IMPORT`'s paths (three lines).

**R2-M3** — The RUNBOOK says the sentinel "checks that no credential is in them", which reads as a scan of the uploaded artefacts — `docs/RUNBOOK.md:299-300` — Scenario: a developer who downloads a failed CI run's `e2e-report` to debug it takes the artefact as scanned-clean and pastes from it freely; the sentinel runs before the suite on an invented login and checks that this configuration keeps nothing (`e2e.yml:58-59`, `check.mjs:1-11`), and no step scans the real run's output. The artefact is clean by construction, but the sentence overstates what was checked, and item C asked for every statement to be checked against the config. — Fix: "… and `npm --prefix frontend run e2e:sentinel`, run before the suite, checks that this configuration keeps no credential in them."

Note, not a finding: `redact.ts:9` says `COOKIE_HEADER` covers "JSON or HAR form"; my probe shows it covers a header line and `"cookie": "…"` JSON, not HAR's `{ "name": "Cookie", "value": "…" }` pairs. No error text Playwright builds carries HAR (HAR lives in traces, local only), and a remembered value is removed from any shape, so nothing leaks; the comment could drop "HAR".

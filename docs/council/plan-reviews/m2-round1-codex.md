1. **BLOCKER — The prescribed test reset deletes `active_config`.** P:241 adds `profile_versions` and `llm_tuples` to `_TRUNCATE`, while P:258–259 adds foreign keys from `active_config` to those tables. PostgreSQL `TRUNCATE … CASCADE` consequently truncates `active_config`, even when its profile pointers are NULL. The existing reset only **updates** that singleton; it does not recreate it (`tests/support/fixtures.py:151`, `tests/support/fixtures.py:187`). Integration tests then start without active configuration. **Fix:** explicitly recreate the seeded singleton after truncation, or use a deletion/reset strategy that preserves it. Test two consecutive resets with the M2 foreign keys installed.

2. **MAJOR — C35 cannot execute the prescribed interleaving.** P:586–605 pauses one `execute_operation` and starts another for the same operation in the same process. The existing registry rejects that second execution with `AlreadyExecuting` (`backend/src/jobhunter/worker/executions.py:75`); `execute_operation` then requeues it (`backend/src/jobhunter/worker/operations.py:541`). Furthermore, the actual reconciler cancels and awaits the first local execution (`backend/src/jobhunter/worker/operations.py:434`), so it cannot later resume as prescribed. I reproduced the registry rejection in memory. **Fix:** test stale claims through independently controlled execution contexts/registries, and separately test the real reconciler’s cancellation behavior. Preserve the singleton and local-exclusion guarantees.

The prescribed call raises `TypeError` when comparing the datetime passed as `interval_s` with zero; reproduced in memory. **Fix:** use `latest_slot_at_or_before(anchor, interval, now)` and test the real save path.

5. **MAJOR — The deployment instructions break worker access to secrets and leave CV storage unprovisioned.** P:730 specifies worker `group_add: ["10011"]`, replacing the YAML-merged application setting `["10010"]` (`deploy/compose.dev.yaml:23–31`). P:743 also mounts `/data/cv` without specifying writable ownership; the current image provisions no such directory (`Dockerfile:30–34`). **Fix:** preserve both supplementary groups, retain the existing secret-permission convention, and explicitly initialize CV-volume ownership. Verify a fresh stack with a nonempty dummy key and a PDF upload.

6. **BLOCKER — Reservation parameters can resurrect an obsolete cap at rollover.** P:546 stores `BudgetParams` in the call context; P:404 initializes each month from the supplied parameters, and P:406 passes those parameters into every reservation. No step refreshes them against active settings. An extraction started before a cap reduction can retry after midnight and create the new month using its old, higher cap. The previous month’s `change_cap` cannot prevent that. Admission also receives both a budget row and potentially stale parameters without defining which cap wins (P:395). **Fix:** make the locked month row authoritative for admission and initialize new months from current settings, with configuration acquired before owner/month locks. Specify how pacing parameters refresh after edits. Add a test combining an old call context, a cap reduction, and rollover—not three independent tests. See S:1141–1164.

7. **MAJOR — Unsettled reservations have no prescribed durable owner token.** P:396–422 requires the reconciler to lock and test the reservation’s original owner predicate. Also define recovery for `EvalRunOwner`: a CLI crash currently leaves its row `running`, so its reserved calls can remain held indefinitely.

Settlement cannot coherently finish both records. **Fix:** explicitly resolve late online responses versus reconciliation, including atomic counter updates and allowed call transitions; record any necessary deviation. Test a live call crossing 15 minutes and simultaneous settlement/reconciliation.

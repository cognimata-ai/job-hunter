**Verdict: REJECT.** The draft needs corrections before implementation. Several prescribed interfaces and tests cannot work against M0, and recovery has gaps affecting quota, receipts and fencing.

References below use **P** for the M1 plan and **S** for spec rev 3.3. This was a static review with read-only reproductions; no files were modified or provider calls made.

**BLOCKER / MAJOR findings**

1. **BLOCKER — The proposed transition registry fails at import.** [P:95](/home/user/job-hunter/docs/superpowers/plans/2026-10-17-m1-collection-pipeline.md:95) makes `disposed_at` both a managed `changed_at` column and `settable`, while [P:203](/home/user/job-hunter/docs/superpowers/plans/2026-10-17-m1-collection-pipeline.md:203) says `TransitionSpec` needs no change. M0 explicitly rejects this overlap in [transitions.py:49](/home/user/job-hunter/backend/src/jobhunter/db/transitions.py:49); I reproduced the `ValueError`. Define a supported atomic timestamp-clearing mechanism. Also explicitly use `CLEAR_REASON` when `rejected→pending` or `deferred→linked`: `reason=None` preserves the old reason ([transitions.py:77](/home/user/job-hunter/backend/src/jobhunter/db/transitions.py:77)), violating the raw-item CHECK.

2. **BLOCKER — Test cleanup deletes the default instances.** [P:103](/home/user/job-hunter/docs/superpowers/plans/2026-10-17-m1-collection-pipeline.md:103) adds `watchlist_companies` and `ats_snapshots` to M0’s `TRUNCATE … CASCADE`, then merely updates default `source_instances`. Both tables are referenced by `source_instances`; PostgreSQL truncation cascades regardless of `ON DELETE SET NULL`. The defaults disappear before the first integration test, and [reset_database:129](/home/user/job-hunter/tests/support/fixtures.py:129) does not reseed them. Reinsert defaults and stop assuming instance ID `1`. Restore mutated settings and ranking state too, otherwise later tests inherit earlier fixtures.

3. **MAJOR — JSearch’s envelope contract contradicts its cursor contract.** [P:1126](/home/user/job-hunter/docs/superpowers/plans/2026-10-17-m1-collection-pipeline.md:1126) requires `data` to be a list but reads `data.cursor`; the synthetic fixtures likewise put items directly in `data` ([P:635](/home/user/job-hunter/docs/superpowers/plans/2026-10-17-m1-collection-pipeline.md:635)). Those cannot describe the same JSON structure. Resolve the envelope from the recorded response before implementing the adapter, scrubber and variants; assert the actual item-array and cursor paths together.

4. **MAJOR — Graph results cannot reach `execute_run` through M0’s protocol.** [P:2356](/home/user/job-hunter/docs/superpowers/plans/2026-10-17-m1-collection-pipeline.md:2356) changes `_invoke` to return state, but [executions.py:128](/home/user/job-hunter/backend/src/jobhunter/worker/executions.py:128) exposes only status/error, and `run_owned` accepts `Coroutine[..., None]` and discards its result. Changing `runs.py` alone cannot implement this. Specify a typed result channel or durable completion lookup while preserving cancellation semantics. Separately, propagated `OutcomeConflict` currently becomes `failed('bug')` at [runs.py:668](/home/user/job-hunter/backend/src/jobhunter/worker/runs.py:668), contrary to I7’s `failed_invariant`; add an explicit branch and test.

5. **MAJOR — Ownership and lock ordering are inconsistent.** [P:1964](/home/user/job-hunter/docs/superpowers/plans/2026-10-17-m1-collection-pipeline.md:1964) locks the run before jobs, reversing [S:312](/home/user/job-hunter/docs/superpowers/specs/2026-10-16-job-hunter-design.md:312). [P:2057](/home/user/job-hunter/docs/superpowers/plans/2026-10-17-m1-collection-pipeline.md:2057) also describes updating postings before recomputing jobs: a stale sweep holding a posting can deadlock with identity holding its job and waiting for that posting. Most directly, [P:2277](/home/user/job-hunter/docs/superpowers/plans/2026-10-17-m1-collection-pipeline.md:2277) gives `embed_awaiting` no owner at all: a superseded attempt can commit returned vectors. Specify job→owner→domain locking and post-I/O ownership checks, with separate reconciler entry points.

6. **MAJOR — C1–C3 recovery can leave the bootstrap probe permanently “in flight.”** [P:981](/home/user/job-hunter/docs/superpowers/plans/2026-10-17-m1-collection-pipeline.md:981) releases/marks ledger entries without updating probe state; only normal settlement sets `probe_failed`. Scenario: the first JSearch reservation sets `probe_used=True`; C1 kills the worker; recovery releases the reservation, but admission still denies `awaiting_window_validation`. C2/C3 similarly bypass failed-probe bookkeeping. Centralize recovery under the window lock: release the probe slot for proven never-dispatched work and mark ambiguous probes failed with their retry deadline. Test these cases against an initially absent window, including subsequent admission and fallback.

7. **MAJOR — SerpApi account refresh is not wired into acquisition.** [P:1542](/home/user/job-hunter/docs/superpowers/plans/2026-10-17-m1-collection-pipeline.md:1542) reads the account during planning; [P:1436](/home/user/job-hunter/docs/superpowers/plans/2026-10-17-m1-collection-pipeline.md:1436) carries an optional cached observation, but the detailed acquisition sequence never refreshes it. After a long primary traversal, fallback either uses stale usage or unnecessarily denies all searches. Require an account read immediately before **each** search, persist its observation/foreign-usage effects before reservation, and read once after the last search ([S:630](/home/user/job-hunter/docs/superpowers/specs/2026-10-16-job-hunter-design.md:630)). Test stale/unavailable account responses and multiple pages.

8. **MAJOR — Coverage statistics are computed before their inputs exist and are not replay-safe.** [P:1642](/home/user/job-hunter/docs/superpowers/plans/2026-10-17-m1-collection-pipeline.md:1642) updates yield using `new_postings` during fetch; postings are created later in identity. `new_native_ids` is not equivalent: rejected/out-of-scope items create no posting. A restart after coverage commit also reruns `update_cell`; unique gap rows do not prevent duplicate EMA/streak updates, and a newly computed window can create another gap. Persist traversal identity/window and an effects-applied receipt; finalize yield after identity. Test a crash after coverage commit.

9. **MAJOR — Grouping loses work after an identity commit.** [P:2172](/home/user/job-hunter/docs/superpowers/plans/2026-10-17-m1-collection-pipeline.md:2172) selects grouping work from transient `RecomputeResult.current_changed`. Kill the worker after linking an item but before grouping: the new attempt skips the linked item and loses that result, so the changed revision is never grouped. The representative reconciler does not discover missing groups. Rebuild grouping work from durable revision occurrences/run attribution, and add this crash boundary.

10. **MAJOR — ATS membership processing counts sightings twice.** Identity already increments `seen_count` and advances observations ([P:1964](/home/user/job-hunter/docs/superpowers/plans/2026-10-17-m1-collection-pipeline.md:1964)). Then [P:2058](/home/user/job-hunter/docs/superpowers/plans/2026-10-17-m1-collection-pipeline.md:2058) calls the same incrementing `apply_sighting` for every snapshot member. One successful board traversal therefore counts twice; a rejected member has no new observation ID to pass. Separate membership availability/reset effects from observation accounting. Persist the mass event’s opening absent set explicitly as well; deriving it from mutable `last_absent_snapshot_id` ([P:2092](/home/user/job-hunter/docs/superpowers/plans/2026-10-17-m1-collection-pipeline.md:2092)) needs a defined update rule.

11. **MAJOR — The fenced-lineage revision test violates the schema.** [P:1926](/home/user/job-hunter/docs/superpowers/plans/2026-10-17-m1-collection-pipeline.md:1926) demands a second revision with the same job/material hash while the first exists. The copied schema has `UNIQUE(job_id, material_hash)` ([S:2028](/home/user/job-hunter/docs/superpowers/specs/2026-10-16-job-hunter-design.md:2028)). This must raise a uniqueness violation. Test refusal while the tainted revision exists, followed by recreation after the purge removes it, or explicitly revise the schema/protocol.

12. **MAJOR — Arbeitnow gap seeking skips fresh collection.** [P:1226](/home/user/job-hunter/docs/superpowers/plans/2026-10-17-m1-collection-pipeline.md:1226) chooses the oldest reachable gap and starts at its seek page. The spec requires every run to read page 1 first ([S:661](/home/user/job-hunter/docs/superpowers/specs/2026-10-16-job-hunter-design.md:661)). With a backlog, new ads can remain unseen while old gaps consume entire runs. Model fresh-head reading followed by seeking within the shared page budget; test sustained growth with an existing gap.

13. **MAJOR — Contract-invalid HTTP 200 handling is contradictory.** [P:1494](/home/user/job-hunter/docs/superpowers/plans/2026-10-17-m1-collection-pipeline.md:1494) expects an HTML 200 to settle `ambiguous` and retain ≤4 KiB, while the adapter/store contracts prescribe `billed` and full 2xx bodies. Keep billing classification separate from envelope validity; preserve the failed receipt on replay, and define conservation for unparseable envelopes. Add a restart test after persisting the invalid 200.

**Recommendations on the six open questions**

- **(a) Page-2 versus coverage:** The undesirable steady-state behavior is real, but the rules are logically compatible: stopping early means incomplete coverage. Implement them as written for M1. Fewer than seven new IDs does not prove chronological overlap or absence of unseen results; adopting that shortcut requires a separately justified spec deviation.
- **(b) Deviation 2:** Approve widening the CHECK. It reconciles the schema with immediate breaker-opening states and six-hour probing. Test timestamp clearing when returning to `ok` or `disabled`.
- **(c) Deviation 6:** Approve the missing-secret policy, with visible reporting and restoration only from `disabled/missing_secret`; preserve unrelated administrative/breaker state. Record the behavioral deviation.
- **(d) Deviation 18:** Approve. `FencedOut` distinguishes stale epoch from an ordinary unclaimable operation. Preserve `None` for the latter and test queue-lock deduplication.
- **(e) Deviation 14:** Approve derived error variants with explicit provenance. Preserve wire structure and identity relationships; retain separate pagination/count-mismatch fixtures so trimming does not erase those tests.
- **(f) V10 later commit:** Approve scheduling it later **within M1**. Acceptance must remain blocked until day-2 evidence is recorded and any identity instability is resolved.
